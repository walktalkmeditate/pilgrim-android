## B2. Reroll — `regeneratingRemainder`

**iOS** (`SeekChain.swift:29-47@c1745e8`):

```swift
/// R17: a reroll replaces the active clearing and regenerates everything
/// downstream as a fresh outbound wander from the walker's current
/// position, under the remaining one-way budget.
func regeneratingRemainder<R: RandomNumberGenerator>(
    fromActiveIndex activeIndex: Int,
    current: SeekPoint,
    remainingBudgetMeters: Double,
    using rng: inout R
) -> SeekChain {
    guard activeIndex >= 0, activeIndex < clearings.count else { return self }
    let kept = Array(clearings.prefix(activeIndex))
    let regenerated = SeekChainGenerator.placeChain(
        count: clearings.count - activeIndex,
        budgetMeters: max(remainingBudgetMeters, SeekEngineTuning.rerollMinBudgetMeters),
        from: current,
        using: &rng
    )
    return SeekChain(clearings: kept + regenerated, budgetMeters: budgetMeters)
}
```

**Android claims, one-for-one:** invalid `fromActiveIndex` (negative or ≥ size) returns `this` unchanged; the reached prefix `clearings.take(fromActiveIndex)` is kept verbatim; the remainder (`size - fromActiveIndex` clearings) is regenerated by the same `placeChain` used for fresh generation, from `current`, under `max(remainingBudgetMeters, REROLL_MIN_BUDGET_METERS)`; the chain's `budgetMeters` field keeps the ORIGINAL budget, not the reroll budget.

**Reroll budget floor** — `SeekEngine.swift:32-35@c1745e8`:

```swift
/// Floor for a rerolled remainder budget (R17) so a regenerated chain is
/// never degenerate — the single source for both the engine's estimate
/// and `SeekChain.regeneratingRemainder`'s clamp.
static let rerollMinBudgetMeters = SeekTuning.minStartDistanceMeters * 2.5
```

= 250 × 2.5 = **625 m**. Hosted in `SeekTuning` on Android (D5). The engine-side estimate that feeds `remainingBudgetMeters` — `SeekEngine.swift:139-141@c1745e8`, `let fractionAhead = 1 - Double(activeIndex) / Double(max(chain.clearings.count, 1))`; `chain.budgetMeters * fractionAhead` — is U3 scope (engine), not U2; quoted here only to pin that `regeneratingRemainder` itself takes the budget as a parameter and only clamps.

## B3. Seed derivation — SHA-256 digest → UInt64

**iOS** (`Pilgrim/Models/Walk/Seek/SeekSeed.swift:14-40@c1745e8`):

```swift
static func make(
    intention: String?,
    moment: Date = Date(),
    fix: TempRouteDataSample? = nil,
    entropy: UInt64 = .random(in: .min ... .max)
) -> UInt64 {
    var hasher = SHA256()
    if let intention, !intention.isEmpty {
        hasher.update(data: Data(intention.utf8))
    }
    update(&hasher, with: moment.timeIntervalSince1970)
    if let fix {
        update(&hasher, with: fix.latitude)
        update(&hasher, with: fix.longitude)
        update(&hasher, with: fix.altitude)
        update(&hasher, with: fix.horizontalAccuracy)
    }
    withUnsafeBytes(of: entropy) { hasher.update(bufferPointer: $0) }

    return hasher.finalize().prefix(8).enumerated().reduce(UInt64(0)) {
        $0 | (UInt64($1.element) << (8 * UInt64($1.offset)))
    }
}

private static func update(_ hasher: inout SHA256, with value: Double) {
    withUnsafeBytes(of: value.bitPattern) { hasher.update(bufferPointer: $0) }
}
```

**Android claims, in digest order:**

1. Intention: UTF-8 bytes, hashed only when non-null AND non-empty (`!intention.isNullOrEmpty()`) — nil and `""` both read as unasked and produce the same seed.
2. Moment: epoch **seconds** as a `Double`, raw IEEE-754 bits (`toRawBits()` ≙ Swift `bitPattern`), **little-endian** bytes (Swift `withUnsafeBytes(of:)` emits native little-endian on all Apple targets). Android takes `momentEpochMillis: Long` and hashes `momentEpochMillis / 1000.0` (D3).
3. Fix (optional): latitude, longitude, altitude, horizontalAccuracy — four Doubles, same bit-pattern little-endian encoding, in that order, all-or-nothing on fix presence. Android takes the domain `LocationPoint`; its optional altitude/accuracy default to `0.0` in the digest (D4).
4. Entropy: `UInt64`/`ULong`, 8 little-endian bytes. Android default draws from `java.security.SecureRandom` (≙ Swift `UInt64.random` on `SystemRandomNumberGenerator`, cryptographically secure).
5. Seed: first 8 digest bytes assembled little-endian — `byte[i] << (8*i)`.

This construction is **byte-identical** to iOS. Pinned by fixtures hand-computed with an independent implementation (python `hashlib` + `struct.pack('<d'/'<Q')`):

| input | expected seed |
|---|---|
| `"let go"`, moment 1 790 000 000 s, no fix, entropy 7 | `16996866564468935451` |
| no intention, moment 1 790 000 000 s, no fix, entropy 7 | `16688271835005157925` |
| `"let go"`, moment 1 790 000 000 s, fix (42.8782, −8.5448, alt 12.5, acc 8.0), entropy 7 | `15651861120168273365` |

## B4. SplitMix64 generator

**iOS** (`SeekSeed.swift:43-61@c1745e8`):

```swift
/// SplitMix64 — a full-period generator whose whole state is the 64-bit
/// seed, so one seed is one seek. Not for cryptography; the secrecy budget
/// is spent inside SeekSeed's hash, this only has to be deterministic and
/// well-mixed.
struct SeekSeededGenerator: RandomNumberGenerator {
    private var state: UInt64
    init(seed: UInt64) { state = seed }
    mutating func next() -> UInt64 {
        state &+= 0x9E3779B97F4A7C15
        var z = state
        z = (z ^ (z >> 30)) &* 0xBF58476D1CE4E5B9
        z = (z ^ (z >> 27)) &* 0x94D049BB133111EB
        return z ^ (z >> 31)
    }
}
```

**Android:** `class SeekSeededGenerator(seed: ULong) : kotlin.random.Random()` with `nextULong()` implementing the identical three-round mix (Kotlin `ULong` `+`/`*` wrap exactly like Swift `&+`/`&*`; `shr` on `ULong` is logical). Raw-output parity pinned by the published SplitMix64 reference vector — seed 0 → `0xe220a8397b1dcdaf`, `0x6e789e6aa1b965f4` — plus a seed-42 sequence cross-computed independently. `nextBits(bitCount)` returns the top `bitCount` bits of one raw output (SplitMix64's best-mixed bits), which routes every `kotlin.random.Random` derived draw through the deterministic core. See D1 for the derived-draw divergence.

## B8. Generation entry point — clamp + count draw

**iOS** (`SeekChainGenerator.swift:45-55@c1745e8`):

```swift
static func generate<R: RandomNumberGenerator>(
    durationMinutes: Int,
    start: SeekPoint,
    using rng: inout R
) -> SeekChain {
    let clamped = min(max(durationMinutes, 1), 240)
    let budget = walkableBudgetMeters(forDurationMinutes: clamped)
    let count = Int.random(in: clearingCountBand(forDurationMinutes: clamped), using: &rng)
    let clearings = placeChain(count: count, budgetMeters: budget, from: start, using: &rng)
    return SeekChain(clearings: clearings, budgetMeters: budget)
}
```

**Android:** duration `coerceIn(1, 240)` BEFORE both budget and band; count drawn uniformly from the band via the injected rng; budget stored on the chain is the clamped-duration budget.

## B9. Placement attempts — best-effort, never fails

**iOS** (`SeekChainGenerator.swift:59-80@c1745e8`):

```swift
static func placeChain<R: RandomNumberGenerator>(
    count: Int, budgetMeters: Double, from: SeekPoint, using rng: inout R
) -> [SeekClearing] {
    var bestCandidate: [SeekClearing] = []
    var bestScore = -Double.infinity
    for _ in 0..<SeekTuning.placementAttempts {
        let candidate = placeOutbound(
            count: count, budgetMeters: budgetMeters, from: from, using: &rng
        )
        let score = constraintScore(of: candidate, budgetMeters: budgetMeters, from: from)
        if score >= 0 { return candidate }
        if score > bestScore {
            bestScore = score
            bestCandidate = candidate
        }
    }
    return bestCandidate
}
```

**Android:** up to 12 attempts; first candidate with non-negative score returned immediately; otherwise the least-bad candidate (max score) is kept — generation NEVER returns empty for `count ≥ 1` and never throws. `internal` visibility (iOS module-internal), shared by `generate` and `regeneratingRemainder`.

## B10. Outbound placement geometry

**iOS** (`SeekChainGenerator.swift:82-120@c1745e8`):

```swift
/// One construction for every case, fresh seek and reroll alike: the
/// chain wanders outward along a random bearing with lateral drift,
/// and the final clearing lands near the crow-flies reach of the
/// walking budget. The seek is one-way — no leg home is budgeted.
private static func placeOutbound<R: RandomNumberGenerator>(
    count: Int, budgetMeters: Double, from: SeekPoint, using rng: inout R
) -> [SeekClearing] {
    let reach = budgetMeters / SeekTuning.streetWindingFactor
    let heading = Double.random(in: 0..<360, using: &rng)
    let side: Double = Bool.random(using: &rng) ? 1 : -1
    let lastFraction = Double.random(in: SeekTuning.finalClearingFraction, using: &rng)

    return (1...count).map { index in
        let isLast = index == count
        let jitter = isLast
            ? 0
            : Double.random(
                in: -SeekTuning.alongJitterFraction...SeekTuning.alongJitterFraction,
                using: &rng
            )
        let along = max(
            (lastFraction * Double(index) / Double(count) + jitter) * reach,
            SeekTuning.minStartDistanceMeters
        )
        let lateral = isLast
            ? 0
            : side * Double.random(in: 0.2...1.0, using: &rng)
                * reach * SeekTuning.lateralWanderFactor // [sic: lateralWanderFraction]
        let onTrack = destination(from: from, bearingDegrees: heading, distanceMeters: along)
        let point = destination(from: onTrack, bearingDegrees: heading + 90, distanceMeters: lateral)
        return SeekClearing(
            center: point,
            radiusMeters: Double.random(in: SeekTuning.clearingRadiusRange, using: &rng)
        )
    }
}
```

(The `[sic]` marks a transcription note only; the shipped source reads `SeekTuning.lateralWanderFraction`.)

**Android claims, one-for-one:**

- `reach = budget / 1.25` (crow-flies conversion).
- ONE heading per chain, uniform `[0, 360)`; ONE lateral side per chain (`Bool` → ±1); ONE `lastFraction` per chain, uniform in `0.85..1.0`.
- Per-clearing draw ORDER: jitter (skipped for the last clearing — the ternary short-circuits, so no rng consumption), lateral magnitude (likewise skipped for last), radius (always drawn, uniform `40.0..60.0`).
- `along = max((lastFraction × index/count + jitter) × reach, 250.0)` — the 250 m along floor applies to EVERY clearing.
- Final clearing: `jitter = 0`, `lateral = 0` → sits exactly on-track at `lastFraction × reach` (subject to the 250 m floor).
- Non-final lateral: `side × U(0.2, 1.0) × reach × 0.12`, offset at `heading + 90°`.
- Center = destination(destination(from, heading, along), heading + 90, lateral).

## B11. Constraint scoring

**iOS** (`SeekChainGenerator.swift:122-154@c1745e8`):

```swift
/// Non-negative when every constraint holds; otherwise the (negative)
/// worst violation, so a best-effort candidate can be kept when the
/// attempt budget runs out. Generation must never fail outright.
private static func constraintScore(
    of clearings: [SeekClearing], budgetMeters: Double, from: SeekPoint
) -> Double {
    var worst = 0.0
    for clearing in clearings {
        worst = min(worst, distance(from: from, to: clearing.center) - SeekTuning.minStartDistanceMeters)
    }
    for (index, first) in clearings.enumerated() {
        for second in clearings.dropFirst(index + 1) {
            worst = min(
                worst,
                distance(from: first.center, to: second.center) - SeekTuning.minSpacingMeters
            )
        }
    }
    var pathLength = 0.0
    var cursor = from
    for clearing in clearings {
        pathLength += distance(from: cursor, to: clearing.center)
        cursor = clearing.center
    }
    let reach = budgetMeters / SeekTuning.streetWindingFactor
    worst = min(worst, reach * 1.1 - pathLength)
    return worst
}
```

**Android:** three constraint families folded into a single worst-violation scalar: every clearing ≥ 250 m from start; every pair ≥ 300 m apart; cumulative start→c1→…→cN path ≤ 1.1 × reach. Score 0 when all pass (not positive slack — `worst` starts at 0).

## B12. Spherical math

**iOS** (`SeekChainGenerator.swift:156-190@c1745e8`) — haversine `distance`, `destination` (bearing + angular distance on a 6 371 000 m sphere), and `bearingDegrees`, header comment: `// MARK: - Spherical math (pure; no Turf/Mapbox dependency in this model)`. Ported formula-for-formula onto `SeekPoint` in `SeekChainGenerator` (`Math.toRadians`/`kotlin.math`). NOT delegated to `domain/GeoDistance.haversineMeters` — that helper takes `LocationPoint` (timestamped fixes); mirroring iOS keeps seek geometry self-contained on `SeekPoint` with the same 6 371 000 m radius, and `destination`/`bearingDegrees` have no existing Android counterpart anyway.

## Divergences (conscious) and resolved ambiguities

| # | Divergence | Reason |
|---|---|---|
| D1 | Derived random draws (`nextInt(range)`, `nextDouble(from, until)`, `nextBoolean`) use `kotlin.random.Random`'s stdlib derivations over the SplitMix64 core, not Swift stdlib's (Lemire `next(upperBound:)` / 53-bit significand draws). Same seed therefore yields a DIFFERENT (but equally deterministic) chain than iOS. | Chains never cross platforms — they are generated and persisted on-device. Per-platform determinism, pinned by tests, is the actual contract; the byte-identical surfaces (seed digest B3, SplitMix64 core B4) are pinned by fixtures. Reimplementing Swift's draw pipeline would be untestable-against-iOS anyway (no iOS fixture values exist). |
| D2 | Swift `ClosedRange` doubles (jitter, lateral, radius, lastFraction) sampled half-open `[a, b)` via `nextDouble(from, until)`. | Kotlin stdlib has no closed-range double sampler; the upper endpoint has probability ~2⁻⁵³. All iOS test bounds (`radius in 40...60`, fraction ≤ 1.01) hold under half-open sampling. |
| D3 | `moment: Date` → `momentEpochMillis: Long`, hashed as `millis / 1000.0` Double; no wall-clock default parameter. | `Long` millis is the house time representation (`LocationPoint.timestamp`, `Clock.kt`); division preserves sub-second mixing at ms granularity (iOS pins only whole-second sensitivity: `addingTimeInterval(1)`). Explicit moment keeps the domain object free of hidden wall-clock reads — Android callers inject `Clock` (iOS defaults `moment: Date = Date()`). |
| D4 | `fix: TempRouteDataSample?` → `fix: LocationPoint?`; `altitudeMeters: Double?` and `horizontalAccuracyMeters: Float?` default to `0.0` in the digest when absent. | `LocationPoint` is the Android pipeline's fix type (iOS uses ITS pipeline type). iOS fields are non-optional because CoreLocation always supplies values (0 / −1 sentinels for invalid); a fixed absent→0.0 rule keeps the digest deterministic. Pinned by test. |
| D5 | `REROLL_MIN_BUDGET_METERS` lives in `SeekTuning` (iOS: `SeekEngineTuning`, `SeekEngine.swift:35`). | U2 does not create the engine. iOS's own comment demands "the single source for both the engine's estimate and `regeneratingRemainder`'s clamp" — U3's engine tuning must reference this constant, not redeclare it. |
| D6 | No `Codable`/serialization conformance in U2 (iOS: `Codable` "so chains ride checkpoints unchanged", `SeekChain.swift:4-5`). | Checkpoint/persistence wiring is a later unit in the Android plan; plain data classes carry no serialization tech choice. The iOS Codable round-trip test is deferred with it. |
| D7 | `placeChain(count: 0, …)` returns an empty list (Swift `(1...0)` would trap). | Kotlin `(1..0).map` is naturally empty. Unreachable on both platforms (band min 1; reroll count ≥ 1 after the index guard) — no crash parity worth engineering. |
| D8 | Generator functions take `rng: Random` as an ordinary parameter (no `inout`). | Kotlin classes are reference types; mutation of generator state is inherent. `SeekSeededGenerator` subclasses `kotlin.random.Random`, so tests and future callers drive the standard API. |
